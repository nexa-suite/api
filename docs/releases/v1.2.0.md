# Nexa API v1.2.0 — preparation candidate

Prepared from `develop` at `cddcbbdbc93eaa8b0290a8b56ba8db6a5d29835c`, the merge commit for [PR #123](https://github.com/nexa-suite/api/pull/123), after [PR #120](https://github.com/nexa-suite/api/pull/120) and [PR #121](https://github.com/nexa-suite/api/pull/121), dated 2026-10-28. The source range from the published `v1.1.0` tag (`775e684c`) contains 21 commits and 141 changed files. This document describes the release candidate; publication requires completion of GitFlow and release checks. Consumer support requires the verified signed tag and corresponding published release.

## Scope

- Apply operation-specific authorization to role-scoped reads and mutations, including Buyer order reads, Catalog product and taxonomy operations, customer/account operations, drafts and logistics.
- Add scoped Catalog filter references and stable product/SKU references; require the existing scoped command ledger for variant-creation idempotency.
- Add Buyer delivery tracking and Driver workday/location operations. Location capture requires an enabled active workday and an assigned active delivery; existing retention policy is unchanged.
- Extend Warehouse location data and inventory lot chronology with structured addresses, production dates and receipt times; preserve lot metadata during transfers.
- Extend own-profile updates with personal identity details.
- Strengthen Business Document access for Warehouse evidence, local private-storage startup and binary download error handling.
- Preserve Sellable SKU identity when accepting material changes and distinguish unavailable draft Warehouse selection.
- Return a Buyer-specific self-account response using the authenticated membership and omit unverified account contact details.

## Contract and migration impact

`GET /api/v1/client-accounts/me` now uses `BuyerClientAccountSelfResponse`. The contact properties remain optional in OpenAPI, but `contactPerson`, `contactEmail` and `phone` are omitted from this Buyer response when they are not verified for the authenticated membership. Consumers must tolerate absent values. `pom.xml`, Render `NEXA_API_VERSION`, runtime OpenAPI metadata and the generated snapshot are aligned at `1.2.0`.

The candidate adds central Flyway migrations V163–V168 and Tenant migrations V24–V25, and updates the Tenant migration manifest. Previously published migration files are unchanged. This is API-repository scope; no complete cross-repository migration parity is claimed.
