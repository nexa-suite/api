# Nexa API v1.1.0 candidate — unreleased

This is an implementation candidate. No v1.1.0 tag, GitHub Release or cloud database cutover is claimed.

## Scope

The candidate keeps central identity and Tenant control separate from each Tenant’s physical business database. Business requests require a ready binding, exact Tenant/Workspace scope and the accepted schema manifest; unavailable bindings fail closed. Local provisioning and credential projection prepare isolated business runtimes without giving the API Docker access or Tenant migration credentials.

The source includes supplier-scoped Buyer wallet recharge and reservation/consumption, commercial credit configuration bounded by existing exposure, explicit Warehouse grants for the verified workflow actor, document/notification/traceability composition, and bounded read-only internal support. Wallet refunds are being completed against the accepted explicit cancellation/refund contract; cancellation itself never credits funds automatically.

## Compatibility and verification

Client compatibility requires the matching Web and Mobile candidates and a runtime with the corresponding Tenant capabilities enabled. Building a client against an API origin does not verify the deployed API’s feature availability. Published Flyway migrations remain unchanged; the candidate adds migrations and updates the required Tenant manifest.

Full API integration verification is pending. Existing integration fixtures must exercise business data in physical Tenant databases while retaining central identity/control data. Connected browser/device flows, provisioning/isolation evidence, final packaging, security gates and signed release publication remain pending. Technical verification, Product Acceptance, System Acceptance and Production Readiness remain distinct.
