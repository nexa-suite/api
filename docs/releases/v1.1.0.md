# Nexa API v1.1.0

This minor release freezes the implemented source for local suite review. Publication is established by the verified signed `v1.1.0` tag and the corresponding GitHub Release; these notes alone do not establish publication. Cloud database cutover and production readiness are outside this review boundary.

## Scope

The candidate keeps central identity and Tenant control separate from each Tenant’s physical business database. Business requests require a ready binding, exact Tenant/Workspace scope and the accepted schema manifest; unavailable bindings fail closed. Local provisioning and credential projection prepare isolated business runtimes without giving the API Docker access or Tenant migration credentials.

The source includes supplier-scoped Buyer wallet recharge and reservation/consumption, commercial credit configuration bounded by existing exposure, explicit Warehouse grants for the verified workflow actor, document/notification/traceability composition, and bounded read-only internal support. Explicit wallet refund commands preserve immutable movements and idempotency; cancellation itself never credits funds automatically.

## Compatibility and verification

Client compatibility requires the matching Web and Mobile candidates and a runtime with the corresponding Tenant capabilities enabled. Building a client against an API origin does not verify the deployed API’s feature availability. Published Flyway migrations remain unchanged; the candidate adds migrations and updates the required Tenant manifest.

The local Compose runtime separates central identity/control data from the provisioned Tenant business database. Catalog and stock fixtures exist in the Tenant runtime; authenticated reads for Buyer, Sales, Warehouse and Logistics were observed. This does not establish a complete order-to-delivery flow or two-Tenant isolation acceptance.

## Review setup and remaining work

Use the repository's local Compose and Tenant provisioning instructions in `ops/tenant-business-database-local.md`; enable the corresponding capabilities and ready Tenant binding before business requests. Missing or mismatched scope fails closed. The current cloud main deployment does not establish support for these new capabilities.

Review the matching Web `v0.2.0` and Mobile `v1.2.0` source boundaries against this local API. Buyer Direct Order presentation, complete cross-device order-to-delivery acceptance, delivery detail/event fixture coverage, production provisioning/cutover and official client distribution remain follow-up work. Implemented endpoints do not imply that every role or user story is accepted.

Mutable business master data follows the accepted normalization direction with explicit Tenant/Workspace isolation columns. No global 3NF/4NF/5NF certification is claimed. Technical verification, Product/UX Acceptance, System Acceptance and Production Readiness remain separate gates.
