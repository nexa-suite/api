# Nexa API v0.5.0

## Summary

Secured identity, tenant/workspace membership and Catalog read vertical slice.

## Highlights

- Added Flyway-managed `iam` and `tenant_management` schemas for PostgreSQL 18.4.
- Added RS256 access tokens with 15-minute TTL and HttpOnly SameSite=Strict refresh cookies.
- Added refresh-session hashing, row locking, rotation and family reuse revocation.
- Added active tenant, workspace and membership verification with canonical surface permissions.
- Secured `GET /api/v1/catalog-items` and its detail route with `catalog:read`.
- Added local-only, env-gated bootstrap and profile-gated OpenAPI for the six approved routes.

## Security impact

No browser token storage, public sign-up, user-management endpoint, Catalog write endpoint, tenant-specific Catalog pricing, stock or cart is included. Domain code remains framework-free; JPA and Flyway stay in infrastructure.

## Validation

- Maven clean package: 86 tests passed, 0 failures, 0 errors.
- Testcontainers migration verification: PostgreSQL 18.4 Alpine, six migrations applied.
- Runtime: health UP, ICISA Carlos/Elena sign-in 200, current session 200, Catalog 200, refresh 200, sign-out 204, invalid Origin 403, wrong surface 401, suspended membership 403 with `ACCESS_CONTEXT_INVALID`.
- Local OpenAPI: six paths, Bearer and refresh-cookie schemes.
- Angular browser smoke: authenticated Platform and Buyer Portal routes rendered ICISA identity and Catalog results at `localhost:4200` and `localhost:4300` using installed Chrome with Playwright.

## Known limitations

Catalog data remains shared local reference data; broader Nexa bounded contexts are future work. Matched authenticated Vue/Angular visual comparison captures remain a separate parity gate.
