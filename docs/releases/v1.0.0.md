# Nexa API v1.0.0

## Release boundary

This is the API repository's first `1.0.0` version boundary, based on the
v0.21.0 contract. It carries the compatible Swagger and OpenAPI runtime
configuration work recorded in the historical v0.21.1 candidate. It does not
change endpoint, operation, request, response or schema semantics. Consumer
support follows the annotated signed-tag and GitHub Release requirements in
the [release policy](../../.github/RELEASE_POLICY.md).

## Scope

- Align the Maven artifact, Render declarative version and committed OpenAPI
  metadata to `1.0.0`.
- Allow Swagger UI (`/swagger-ui/**`, `/swagger-ui.html`) and OpenAPI docs
  (`/v3/api-docs/**`) in non-local profiles when `nexa.swagger.enabled` /
  `NEXA_SWAGGER_ENABLED=true` is explicitly configured.
- Keep Swagger UI and OpenAPI enabled by default for the `local` profile and
  disabled by default in non-local profiles.
- Adjust Content Security Policy headers only when Swagger UI is enabled.
- Grant the seeded warehouse to the seeded WAREHOUSE membership through the
  existing BC-01 access-context and explicit warehouse-grant path when the
  opt-in local development bootstrap runs. No implicit grant is added to
  ordinary warehouse creation or non-local runtime flows.
- Retain the `DoubleSupplier` registered by each technical state gauge for the
  meter's lifetime. This prevents Micrometer's weak-reference default from
  clearing the supplier and reporting `NaN`; it changes no API contract or
  business behavior. See the [Micrometer gauge reference](https://docs.micrometer.io/micrometer/reference/concepts/gauges.html).
- Configure the pull-request OpenAPI compatibility workflow to compare against
  the published v0.21.0 and v0.20.0 baselines, earlier published consumer
  baselines, and the PR base snapshot.

## Verification and acceptance boundary

The combined source was verified at commit
`cc9df659fa1d88d97ad8dc373429d0ea486a1954`, with the v1.0.0 release metadata
changes present in the working tree. The command was:

```text
./mvnw clean verify -Dnexa.integration.enabled=true -Dspring.datasource.hikari.maximum-pool-size=32
```

It used the CI-compatible ClamAV 1.4.3 and WireMock 3.13.1 test adapters and
the PostgreSQL 18.4 Testcontainers integration database. Maven reported
`BUILD SUCCESS`: 694 tests, 0 failures, 0 errors and 0 skipped. This run
includes the local bootstrap-grant regression and the technical gauge supplier
test.

The local fixture grant uses the existing explicit-grant path. It changes no
Render configuration or runtime authorization behavior and does not verify the
separately reported remote warehouse or reservation-to-Sales/Dispatch
visibility behavior. The Maven run did not deploy or validate a running Render
service, and no local API runtime/database update is represented here.

These repository-level checks do not establish Product Acceptance, complete
Nexa System Acceptance or Production Readiness. Those gates require their own
applicable evidence. Consumer support is tied to the verified signed tag and
corresponding GitHub Release, as defined by the release policy.
