# Nexa API v0.2.0

Released: 2026-07-28

## Summary

Shared HTTP foundations and canonical catalog seed authority for Nexa Suite.

## Breaking changes

No intentional breaking changes.

## Added

- `X-Correlation-ID` acceptance/generation, response propagation and temporary MDC context cleanup.
- Safe Problem Details error model with stable error codes and validation field list.
- `CatalogSeedItemRecord`, loader, validator and integrity exception under catalog infrastructure.
- Exact 50-item seed at `seed/catalog/catalog-items.v1.json` and SHA-256 checksum.
- Spring Boot build-info generation for `/actuator/info`.

## Changed

- Application metadata uses generated build version and durable API description.

## Fixed

- Framework validation, malformed JSON, not-found, method-not-allowed and unexpected errors now use controlled Problem Details responses.

## Security

No authentication or authorization was added. Correlation IDs accept only safe bounded characters; responses do not expose stack traces, class names, SQL, paths, secrets or uncontrolled exception details.

## Data and assets

The canonical seed is copied byte-for-byte from the approved ASP.NET reference. SHA-256: `c9fdb629c3996f78918081a6e7f6598ce44c8ede05a8208c7f77785367ca096b`. No database or persistence migration is included.

## API contract impact

No catalog REST endpoint, catalog page contract or success/data wrapper was added. Error responses for framework-level failures use RFC Problem Details fields plus `code`, `correlationId` and sorted validation `errors` where applicable.

## Auth/authorization

None. This release does not authenticate callers or enforce roles, tenant membership or workspace identity.

## Deprecations/sunset

None.

## Rate limits

None configured.

## Data migration

None. The seed is a classpath resource loaded on demand and is not persisted.

## Upgrade instructions

Run `./mvnw clean test`, `./mvnw clean package`, then inspect `/actuator/info` and `/actuator/health`.

## Validation

Maven clean tests, package build, seed integrity tests and HTTP Problem Details tests passed on the release branch.

## Known limitations

No business endpoints, persistence, authentication, authorization, tenant runtime, deployment or frontend integration are included.
