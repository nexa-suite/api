# Nexa API v2.0.3

Compatible cloud-read and Swagger usability patch based on published v2.0.2.
Publication requires the signed tag, GitHub verification and GitHub Release.

## Behavior

Swagger opens `complete` with operation groups expanded. `presentation` remains
an optional smaller view; HTTP operations use the same origin as the page.
This changes documentation navigation, not API authorization or available
business capabilities.

When `tenant-cloud` and `NEXA_TENANT_BUSINESS_CLOUD_OPERATIONS_READ_ENABLED=true`
are configured with the existing verified cloud router, the current inventory
list/lot/detail, per-Warehouse availability, fulfillment work-list/detail and
physical-allocation GET routes read the verified physical Tenant
database. The same permissions, Tenant/Workspace scope, Warehouse grants,
filters and pagination apply. Cloud fulfillment details require access to the
linked allocation Warehouses before returning the resource. PostgreSQL enforces `READ ONLY` and
`REPEATABLE READ` on these reads.

General Warehouse and Fulfillment command flags stay off. This patch does not
enable stock mutations, picking transitions, background workers, orders,
payments or other unsupported cloud capabilities. Showing an endpoint in
Swagger does not attest its readiness in a deployment.

## Compatibility and deployment

The consumer contract differs from v2.0.2 only in `info.version`. There is no
new database migration, schema grant, APK endpoint, response-field change or
client dependency. Use existing central and Tenant credentials/bindings; do
not redirect business queries into central tables.

Keep `NEXA_TENANT_BUSINESS_WAREHOUSE_OPERATIONS_ENABLED=false` and
`NEXA_TENANT_BUSINESS_FULFILLMENT_DELIVERY_ENABLED=false`. Enable only the new
read flag after verifying the published source and deployment. Existing data
may legitimately yield empty lists; fixtures or new business facts must never
be fabricated to make dashboard totals nonzero.

## Validation

`CloudMobileOperationsHttpIT` verifies the real read composition with isolated
PostgreSQL, HTTP authentication and command guards. `TenantBusinessDatabaseRouterIT`
checks physical isolation, scope and PostgreSQL write rejection. Configuration
and architecture tests cover opt-in selection and preserved module boundaries.
The scoped PostgreSQL/configuration/architecture/contract verification passed
78 tests. A separate `clean verify` recorded 1,250 tests, zero failures/errors
and 373 conditional skips. The two OpenAPI checker suites passed 58 tests;
strict comparison against v2.0.2 found no incompatible contract change.
Live verification must separately exercise the deployed API and mobile clients.

## Rollback

Disable the new cloud-read flag and deploy the previously verified v2.0.2
source if needed. No data rollback or credential rotation is required by this
patch. Preserve published signed tags and historical business facts.
