# Nexa API v0.16.1

Backend V1 Freeze-Closure Patch.

## Scope

- v0.16.0 remains immutable history; this release is a compatible correction patch.
- No new product semantics, bounded context, mobile domain model or provider-specific business contract is introduced.
- The canonical eleven Blueprint bounded contexts and V1-V91 Flyway history remain unchanged.

## Corrections

- Sign-out now reports durable revocation failures as canonical 5xx ProblemDetail responses and clears browser refresh cookies only after successful revocation.
- Refresh-token reuse remains detectable after the bound membership loses its active authorization policy.
- Manual Sales Order idempotency claims are serialized before side effects, preventing concurrent duplicate orders or orphaned claims.
- Existing card-payment claims replay after a successful provider webhook settles the receivable.
- Workspace activation/creation provisions the stable `SYSTEM_WORKFLOW` actor; stale canonical outbox and Stripe inbox work at retry limits become durable `DEAD_LETTER` records.
- Runtime PostgreSQL validation rejects effective unsafe role paths, replication/database/schema creation privileges, owned application objects and unapproved executable `SECURITY DEFINER` functions.

## Database policy

Migration `V92__close_stripe_webhook_dead_letter_gap.sql` is additive and only expands the Stripe inbox status check to include `DEAD_LETTER`. V1-V91 are preserved and no data is deleted or rewritten.
