# Nexa API v0.15.0

Fulfillment & Financial Completion implementation wave.

## Scope

- Canonical API module roots aligned with the eleven Blueprint bounded contexts. See [the map](../architecture/bounded-context-module-map.md).
- BC-05 Inventory Availability owns concrete physical allocation: FEFO lot selection, safety-stock protection, release of unpicked quantities and consumption at dispatch.
- BC-06 Fulfillment & Delivery owns `ALLOCATED → PICKING → PICKED → PACKED → STAGED → READY_FOR_DISPATCH → HANDED_OVER`, delivery attempts, partial/final quantity outcomes, continuation delivery, POD and temperature evidence.
- BC-07 Credit & Receivables owns receivable applications, immutable financial adjustments, ledger entries and refund/credit obligations. BC-08 Payments remains provider and payment-lifecycle authority.
- BC-11 Business Traceability uses the existing append-only `audit.event` and `integration.outbox_event` infrastructure; no second audit subsystem is introduced.
- Additive Flyway migration `V91__fulfillment_financial_completion.sql`, tenant/workspace RLS, append-only evidence tables, idempotency and optimistic concurrency.
- OpenAPI routes are generated from the canonical v0.15 controllers; legacy v0.14 routes remain compatibility contracts.

## Canonical published events

The wave uses the frozen event vocabulary where new publication is required:
`PhysicalAllocationCreated.v1`, `FulfillmentShortage.v1`,
`DeliveryCompleted.v1`, `ContinuationDeliveryCreated.v1`,
`ReceivablePosted.v1`, `BusinessFactTraced.v1`.

Existing v0.14 event names remain compatibility history and are not silently
renamed by this migration.

## Explicitly out of scope

New Blueprint bounded contexts, frontend/mobile changes, fiscal/SUNAT provider
certification, accounting settlement beyond the BC-07 ledger foundation,
IoT ingestion, BI/analytics redesign, deployment/publication and changing the
Blueprint repository.
