# Nexa API v0.21.0

**Status:** unreleased candidate.

This candidate establishes the next compatible API version after the published
v0.20.0 release. It does not claim Product Acceptance, System Acceptance or
Production Readiness. Consumer support begins only after the required checks,
an annotated SSH-signed tag and the corresponding GitHub Release pass.

## Version and compatibility boundary

- Maven, Render declarative configuration and the committed OpenAPI document
  report version `0.21.0`.
- Pull-request OpenAPI compatibility is checked against the published v0.20.0
  contract, followed by v0.19.0, v0.18.0 and the historical v0.17.1 upgrade
  baseline.
- No endpoint, response, request or schema removal is introduced by this
  candidate.

## Authentication and authorization review

- Native identity sign-in continues to require the explicit `X-Nexa-Client:
  NATIVE` transport without a browser `Origin` header.
- Pre-context tickets remain opaque, short-lived, single-use credentials and
  are accepted only on the native transport. Browser requests continue to use
  the configured Origin and refresh-cookie rules.
- JWT access requests continue to revalidate the persistent session, active
  Tenant/Workspace membership, roles, permissions and authorization version
  against server state. JWT claims and client headers do not become authority.

## Data and integration boundaries

- No Flyway migration or published migration is added or modified.
- Tenant isolation, forced RLS, runtime least privilege, bounded-context
  ownership and external transport validation remain unchanged.
- The existing fail-closed disabled scanner mode and deployment configuration
  remain available through the existing environment contract.

## Verification status

Local candidate verification completed with the repository's clean Maven
verification and real test adapters: 678 tests, zero failures, errors or
skips, including integration, architecture, RLS, authentication, OpenAPI and
database checks. The packaged artifact is `api-0.21.0.jar`.

The four local OpenAPI compatibility checks against v0.20.0, v0.19.0, v0.18.0
and v0.17.1 also pass. The remote security/load, CodeQL, dependency and
container gates, together with runtime/provider evidence and client or
physical-device acceptance, remain separate publication checks.
