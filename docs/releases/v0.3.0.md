# Nexa API v0.3.0 — Catalog Domain Foundation

## Summary

Catalog Management domain foundation and repository governance update.

## Highlights

- Pure `CatalogItem` aggregate with explicit value objects and invariants.
- Anticorruption mapping from the canonical seed import record.
- Stock ownership kept outside Catalog Management.
- Compatibility constraints for Angular, Kotlin, Swift and future automation clients.
- Domain purity and seed mapping tests.

## Domain decisions

Catalog Management owns the commercial product definition. Warehouse owns physical stock, lots, reservations and movements. Brand and Category are value concepts until independent lifecycle evidence exists. No generic entity, repository or persistence abstraction is introduced.

## Legacy differences

Legacy tenant assignment, stock mutation, command-dependent aggregates, base entities and independent Brand/Category aggregates are deliberately excluded. Import metadata remains in Infrastructure and is not aggregate state.

## Breaking changes

None to published HTTP behavior.

## API contract impact

No REST business endpoint was added or changed. No Catalog Management object is exposed over JSON.

## Authentication and authorization

No authentication or authorization behavior changed.

## Data and persistence

No database migration is required. The seed remains a classpath import source and is not persisted.

## Security

Coordinated vulnerability reporting guidance is documented. No credentials, tokens or production data are included.

## Validation

Domain invariant tests, domain purity tests, seed mapping tests, Maven tests and package validation passed on the release branch.

## Known limitations

No catalog REST endpoint, persistence, tenant ownership decision, editable catalog use case or frontend catalog model is included.

## Upgrade instructions

Run `./mvnw clean test` and `./mvnw clean package`.
