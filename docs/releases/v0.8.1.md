# Nexa API v0.8.1

## Summary

Operations release stabilization for the published commercial, Warehouse and Logistics baseline.

## Highlights

- Sales Order creator identity remains the internal Membership identity and buyer identity remains separate.
- Sales Order lifecycle transitions are decided by the aggregate; concurrent conversion replays one logical order for one idempotency key.
- Route start is coordinated by an Application service with Warehouse fulfillment through an explicit port.
- Dispatch number generation starts at `DO-YYYY-000001` for future clean yearly counters through a forward-only migration.
- OpenAPI metadata describes the implemented Warehouse and Logistics contracts accurately.

## TASK-011 boundary

This release adds only compile-safe internal document-subject vocabulary and read contracts. Business Documents, storage, files, uploads, downloads, invoices, payments and SUNAT are not implemented.

## Validation

Validation evidence is recorded from the release gate; no release claim is made from a partial gate.
