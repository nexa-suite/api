# Nexa API v2.0.1 — release candidate

Compatible deployment patch on the published v2.0.0 source line. This candidate is not a published release until the signed tag and GitHub Release exist.

## Scope

- Reuse existing Tenant-routed catalog list/detail/filter, Buyer own-account, authorized Platform customer list/detail and notification HTTP adapters through the explicit `tenant-cloud` profile. All capability flags remain off by default.
- Restore existing read-only SKU-code/GTIN resolution for Operations scanning through the Tenant-routed catalog reader; catalog-management commands remain disabled.
- Restore the existing customer-selection reads needed by Operations Sales: list/detail retain server permission checks, assigned Sales ownership and Tenant/Workspace scope; all customer mutations remain disabled. Generic catalog reads do not establish customer-specific pricing or offers.
- Add a verify-only Neon deployment CLI for physical Tenant/database identity, Workspace anchor, exact applied Tenant migrations, migration-manifest digest and restricted runtime/policy-writer roles. It does not provision, migrate, change grants or attest central bindings.
- Preserve local provisioning checks while sharing physical readiness checks. Neon administrator memberships have an explicit narrow policy; application roles gain no owner membership or central fallback.
- Permit the existing HTTP inbox, unread count, read-state and personal notification preferences when independently enabled. Workspace notification-settings writes fail closed in cloud because their central audit is outside the Tenant transaction. Push delivery, projections and callbacks remain outside this delivery.
- Record the Owner-reviewed historical OpenAPI migration and check this patch against published v2.0.0 in CI. The strict compatibility checker is unchanged.

## Contract and consumer impact

The OpenAPI document differs from published v2.0.0 only in `info.version` (`2.0.1`); the strict comparison reports zero incompatibilities. No new business endpoint or Product rule is introduced. The privacy removal of four Buyer self-account fields remains unchanged. Global delivery policy remains five business days in America/Lima without holidays.

The Product Owner explicitly approved the exact v2.0.1 migration, candidate SHA256 `de215cb0a335b717951fc3fb424bdf2e08d926643ecbbdfc7a085bb955bb13a3`; see [decision record](https://github.com/nexa-suite/api/pull/139) and [manifest](../openapi/migrations/v2.0.1.json). This contract decision does not replace GitHub review or CI.

## Deployment and verification limits

Follow [cloud routing configuration](../../ops/tenant-business-database-cloud.md) and [verify-only procedure](../../ops/tenant-business-database-cloud-verification.md). Central and Tenant databases require separate Neon branches/computes, dedicated roles, TLS verification, fresh physical verification and guarded central binding attestation. Disable restored scheduled/outbox work during bounded rehearsal. No copied READY row is fresh verification.

Source publication does not establish a managed deployment, complete Buyer or Operations business journeys, Product/UX Acceptance, System Acceptance, academic acceptance or Production Readiness. Purchase Request commands, sales, inventory, fulfillment, finance and unsupported callbacks/workers remain disabled in this bounded cloud composition.

## Rollback

Disable cloud capability flags and return to the previously verified source release using the deployment platform. Preserve central and Tenant data; do not redirect Tenant business operations into central tables, rewrite published migrations or modify signed historical tags. Restore binding state only through a reviewed expected-version operation.
