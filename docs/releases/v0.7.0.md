# UNRELEASED HISTORICAL CANDIDATE — Nexa API v0.7.0

This document preserves candidate content later consolidated into published `v0.8.0`. `v0.7.0` has no published tag or GitHub Release.

## Summary

Commercial correctness for the Purchase Request to Sales Order boundary, with tenant-scoped persistence, immutable order snapshots and a secure persisted change feed.

## Highlights

- Sales Orders can be created only from an `APPROVED` Purchase Request through an atomic, idempotent conversion.
- Server-generated `SO-YYYY-000001` numbering is scoped by tenant, workspace and year.
- Sales Order status is explicit: `PENDING`, `CONFIRMED`, `REJECTED` or `CANCELLED`.
- Purchase Request and Sales Order event timelines expose stable event identifiers.
- PostgreSQL-backed SSE change feed revalidates the bearer session and access context during bounded streams.

## Security and data integrity

- Buyer reads remain client-account scoped; Sales Order mutations require `sales:write` and `SALES` or `COMPANY_OWNER` membership.
- Conversion requires `Authorization`, `If-Match` and `Idempotency-Key`; prices and commercial fields are copied from server-side Purchase Request snapshots.
- Sales Order lines, snapshots, lifecycle events, idempotency records and change-feed events are append-only or protected by database constraints and triggers.
- Change-feed payloads contain public status metadata only; tenant, workspace and buyer scope are resolved server-side.

## API changes

- Added Sales Order conversion, list/detail, event, confirmation, rejection, cancellation and fulfillment-candidate contracts.
- Added Purchase Request event timeline query.
- Added `/api/v1/change-feed/stream` with `Last-Event-ID`, bounded replay, heartbeat and session/context revalidation.

## Known limitations

- Sales Order conversion does not reserve inventory, capture payment or create dispatch documents.
- Fulfillment candidates are read-only; Warehouse, Logistics, Invoicing and Analytics bounded contexts remain outside this release.
- Vue visual parity is not certified without matched authenticated Vue and Angular captures.
