# Nexa API v0.13.0

## Summary

Backend Foundation Closure release for the Nexa API modular monolith.

This is a technical-foundation release. It does not introduce new V1 product semantics,
new bounded contexts or a change of stack.

## Included baseline

- Canonical outbox identity, occurrence keys, durable retry and safe published-payload retention.
- Lease expiry recovery and claim-token fencing for security notifications, document generation and payment reconciliation workers.
- Provider-status-aware Stripe reconciliation outcomes, durable manual retry idempotency, request-hash conflict detection and bounded retry attempts.
- PostgreSQL migrations `V87` and `V88`, including RLS coverage for the durable retry store.
- OpenAPI compatibility checks, RLS scope classification and documented worker contracts.
- Release-branch CI coverage for CodeQL, security/load and supply-chain gates.

## Contract and operational notes

- External payment-provider calls remain outside database transactions.
- Reconciliation worker pagination is keyset-based across all workspaces; bounded batches do not permanently starve later workspaces.
- Pending provider outcomes return `202`; technical/provider failures are surfaced as problem details rather than false success responses.
- Published outbox payload retention redacts payload data only after the configured retention period; event identity, ordering and deduplication state remain intact.

## Validation

- Clean Maven test suite: 408 tests passed, 0 failures, 0 errors; 106 profile-dependent skips.
- Fresh and upgrade PostgreSQL/Flyway validation passed through migration `V88`.
- Docker build-time verification passed.
- OpenAPI compatibility, architecture, RLS, CodeQL, security/load and supply-chain gates passed.
