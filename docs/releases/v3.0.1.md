# Nexa API v3.0.1

Buyer can open existing purchase requests, sales orders, delivery events and
receipt history in the cloud profile. The API checks the active Buyer account
and Workspace and reads from the verified Tenant database.

The Docker image stores Spring Boot dependencies in separate layers so Render
can reuse them across application updates. The build runs the Maven test suite.

## Deployment

Use the current schema and set
`NEXA_TENANT_BUSINESS_CLOUD_BUYER_JOURNEY_READ_ENABLED=true` after verifying the
cloud router and Tenant binding. See the
[cloud routing guide](../../ops/tenant-business-database-cloud.md).
The opt-in covers the listed reads. Order creation and fulfillment commands
still require their cloud composition.

## Verification

The HTTP integration tests cover requests, orders and delivery reads in a
separate PostgreSQL Tenant database. They check that another account's records
return 404 and that Buyer delivery responses omit internal event fields.
The OpenAPI snapshot changes only the release version.
