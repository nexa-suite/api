# Nexa API v0.18.0 — Identity-First Access Context Selection

This document records the API implementation candidate for identity-first
native sign-in and explicit work-context selection. It does not represent a
published release, production-readiness claim or complete Nexa product
acceptance.

## Starting baseline

- The current tagged repository baseline is `v0.17.1`.
- The repository contains v0.17.0 release notes and no historical v0.17.1
  release-note file. No v0.17.1 release history is reconstructed here.

## Implemented contract

- `POST /api/v1/authentication/identity-sign-in` authenticates identity before
  work-context selection. Zero eligible contexts returns `NO_WORK_CONTEXT`; one
  context creates a scoped session; two or more contexts return a five-minute,
  single-use selection ticket.
- `GET /api/v1/me/access-contexts` lists current eligible contexts, and
  `POST /api/v1/me/access-context-selections` revalidates and selects one using
  the ticket. Selection rechecks identity, surface, membership, Tenant,
  Workspace and their current status and relationships.
- Tickets are opaque in the API, stored as a digest, excluded from audit
  metadata, and consumed atomically. The new flow uses the explicit NATIVE
  transport. Existing browser sign-in, refresh, sign-out and session contracts
  remain available.
- Session projections include Tenant and Workspace names. The implementation
  does not add roles, Bounded Contexts, surfaces or in-session context-switch
  semantics.

## Database

- Additive Flyway migration V101 creates
  `iam.access_context_selection_ticket`. It stores the digest, user, surface,
  issuance, five-minute expiry and consumption state; it does not persist a
  selected Tenant or Workspace.
