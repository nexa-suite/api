# Nexa API v0.18.0

**Released:** 2026-09-25

**Status:** consumer-stable API contract

This release closes the accepted API contracts needed by Platform, Buyer
Portal, and Operations Android. It establishes an API consumer baseline; it
does not claim complete Nexa System Acceptance, full-system Production
Readiness, Web or Mobile Product acceptance, or Buyer Mobile completion.

## API contracts

- Native identity-first sign-in supports zero, one, or multiple eligible
  Tenant/Workspace contexts. Multiple contexts use an opaque, short-lived,
  single-use selection ticket. Existing workspace-scoped browser sign-in and
  cookie refresh remain compatible.
- Session responses include Tenant and Workspace names in addition to existing
  context identifiers and authorization data.
- Purchase Requests use the current lifecycle and immutable Material Change
  history. A Buyer can accept or reject a proposal; rejection preserves the
  original commercial terms. The legacy cancellation operation remains
  available as a deprecated compatibility route, while Buyer withdrawal is
  the canonical termination operation.
- Warehouse Transfer uses the scoped `REQUESTED` → `IN_TRANSIT` → `RECEIVED`
  lifecycle. Transit does not become sellable destination stock.
- Business Document replacement links a new immutable document to its
  predecessor without overwriting the issued document.
- Buyer Catalog requires an active server-resolved Customer Account
  relationship and returns only the Buyer-safe Sellable Availability
  projection. Buyer draft collection supports authorized resume without
  creating a Purchase Request or commitment.
- BC-03 uses one authoritative offer resolver for Buyer catalog responses and
  Sales snapshots: Base Price, an applicable Price List permitted by current
  Customer Terms, and at most one eligible Promotion. Submission and other
  authoritative Sales decisions revalidate the current offer.
- Credit exposure is projected from existing BC-07 credit limits,
  reservations, and receivable exposure under Tenant and Customer
  authorization.

## Database and ownership

- Official additive migrations are V101–V105 and V107. The supported upgrade
  baseline is v0.17.1/V100. V106 is intentionally absent from the official
  migration line.
- The experimental BC-05 `warehouse.stock_temperature_evidence` migration is
  excluded. Temperature evidence remains on the existing BC-06 Logistics
  `logistics.temperature_evidence` and `logistics.temperature_excursion`
  model introduced by V91.
- The current RLS inventory classifies all tables through V107. Every directly
  Tenant/Workspace-scoped table has forced RLS; pre-context access remains
  bounded by explicit transaction-local lookup capabilities.

## Compatibility and scope

- v0.17.1 remains the tested data-upgrade baseline. Existing browser
  workspace-scoped authentication is retained.
- Historical Purchase Request status values remain readable without becoming
  current lifecycle transitions. The compatibility cancellation route is
  documented as deprecated.
- This release does not complete Web or Operations Mobile Product scope and
  does not implement Buyer Mobile.
