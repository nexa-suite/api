# Nexa API v0.14.0

Commercial and Inventory Core.

## Scope

- Commercial Commitment owned by Sales Commitment (BC-04).
- Direct Order path: `DIRECT_ORDER` commitment, authoritative inventory backing, required credit reservation where applicable, then Sales Order confirmation.
- Purchase Request submission with atomic commitment, backing and credit decisions.
- Authoritative price/currency snapshots and immutable Sales Order origin metadata.
- Deterministic multi-warehouse availability backing with safety-stock protection and no physical lot allocation.
- Absolute Purchase Request expiry and release of active commercial backing and credit reservation.
- Durable idempotency with request-hash conflict detection and concurrency-safe credit reservation.
- Additive PostgreSQL migrations `V89__commercial_inventory_core.sql` and `V90__close_v014_idempotency_upgrade_gaps.sql`, tenant/workspace RLS and generated OpenAPI contract.

## Explicitly out of scope

Fulfillment, picking, dispatch, delivery, financial settlement, accounting, SUNAT, refunds redesign, advanced receivables, IoT, BI, mobile and new published events without Blueprint authorization.

## Validation

The release candidate must pass clean Maven verification with integration enabled, fresh and upgrade PostgreSQL migrations, architecture/modularity, RLS, concurrency, idempotency, OpenAPI compatibility, security/load, CodeQL, supply-chain, container and dependency-review gates before publication.

## SCM

The release is published only from the fully validated `v0.14.0` release branch with signed commits and an annotated signed tag whose local signature verification succeeds.
