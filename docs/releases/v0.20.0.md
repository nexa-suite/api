# Nexa API v0.20.0

Consolidated server support for Operations Mobile Wave 4. Nexa API versions independently from the Android client.

## Changes

- Tenant/Workspace/Warehouse authorization and explicit object grants remain server-authoritative.
- Exception classification, BOM coordination, authorized cold-chain dispositions and execution HOLD preserve domain authority and traceability.
- Driver tracking is bounded by active operational shift; Buyer visibility is bounded by its active Delivery and raw coordinates expire within the approved retention window.
- Dispatch missing-window planning and load attestations preserve existing commercial windows and authoritative compatibility checks.
- Correct inventory pagination, response timestamp precision and exact coordinate replay identity; update vulnerable Jackson dependencies.
- Permit the explicit BOM role in invitations through forward migration V144. Token acceptance resolves the exact invitation scope before row locking, then revalidates the token and pending state without widening RLS policies.
- Give new operational OpenAPI schemas unique names while preserving published consumer contracts and application-layer independence.

## Validation and boundaries

Promotion requires the unchanged integration, security, dependency and compatibility gates. The compatibility matrix includes develop and the v0.19.0, v0.18.0 and v0.17.1 consumer baselines. Local runtime evidence uses the non-BYPASSRLS application role.

V143 and V144 are forward migrations; published migration history remains immutable. There is no automatic inventory recreation in transit, automatic stock release through exception closure, or new financial authority.

The inherited Catalog pricing-preview snapshot naming defect is documented in `docs/openapi/README.md`; its published schema is preserved rather than silently changed. Production provider readiness, physical-device evidence and Product/System acceptance remain distinct from this technical release.
