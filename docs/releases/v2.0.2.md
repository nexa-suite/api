# Nexa API v2.0.2

Compatible Swagger presentation and verification patch based on published v2.0.1.
Publication requires the signed tag, GitHub verification and GitHub Release.

## Changes

- Swagger UI opens the small `presentation` group for authentication, catalog taxonomy and warehouses. `complete` and `/v3/api-docs` preserve the full contract and compatibility aliases.
- Tags start collapsed, the global schema panel is hidden, filtering and request durations are enabled, and syntax highlighting and persisted authorization are disabled.
- Swagger calls the same origin as the page, including HTTPS behind a reverse proxy. The demonstration obtains a token through native sign-in outside the browser, then uses bearer authorization, idempotency, resource-version headers and logical deactivation.
- Historical migration evidence remains immutable. A later patch may reuse it only when its contract differs solely in `info.version`, the reviewed snapshot digest matches, and all original baseline, finding and approval checks pass.
- The manual-order idempotency fixture uses a future date instead of an expired fixed date.

## Deployment compatibility

No new required environment variables, dependencies, database migrations, credentials or capability flags. Maven, packaged build metadata, OpenAPI and the Render manifest use 2.0.2. Existing Render environment values and Neon database bindings remain applicable; packaged BuildProperties takes precedence over the optional application version environment value.

No business route, authorization requirement, session transport, database boundary or APK response body changes. Existing cloud capabilities remain bounded: catalog-management commands and other unsupported mutations stay unavailable. The local demonstration requires provisioned Tenant fixtures and enabled capabilities. The Swagger group is navigation, not a capability grant.

Render deploys the configured branch, not GitHub release objects. With auto-deploy disabled, publication must be followed by an explicit deployment of the reviewed `main` commit. Existing secrets must be retained; do not replace the environment with a partial variable list.

## Verification

See [Swagger procedure](../openapi/README.md) for the reproducible authenticated CRUD check. Run the repository CI workflows for integration, architecture, security and consumer compatibility. Source publication and a successful build do not establish complete system acceptance or production readiness.

## Rollback

Deploy the previously verified v2.0.1 commit. No schema rollback or secret rotation is required by this patch. Preserve data, signed historical tags and existing capability restrictions.
