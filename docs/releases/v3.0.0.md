# Nexa API v3.0.0

This release brings the mobile terms, notification, Warehouse, and transfer
evidence changes together.

## Changes

- Publish the current mobile terms and record acceptance by individual account
  and document version.
- Encrypt push destinations and route eligible Firebase notifications through a
  dedicated worker scoped to the active Workspace and authorized recipients.
- Keep Warehouse picking, packing, and staging work visible through handover.
- Allow a Buyer with payment creation permission to attach proof to a receivable
  in their active relationship. File checks and Finance review still apply.
- Prepare the IAM-owned V190 migration for restricted Neon roles. Tenant
  migrations V44–V48 support encrypted destinations, scoped notification
  processing, and idempotent audit insertion.

## Deployment

Apply central V190 and Tenant V44–V48 with the
[database preparation steps](../../ops/README.md) and
[cloud routing guide](../../ops/tenant-business-database-cloud.md).
Verify the Tenant binding and manifest before enabling the cloud router or FCM.

The cloud profile supports the enabled reads and scoped notifications. Purchase
requests, Warehouse commands, fulfillment writes, and payments require their
cloud composition before they can run there.

## Verification

The local API validation followed one Buyer request through Sales, Warehouse,
Driver delivery, Buyer receipt, and the matching inbox item. The combined
candidate passed 40 targeted tests covering that flow, transfer proof, and
migration and worker permissions. Cloud delivery and device validation remain
separate.
